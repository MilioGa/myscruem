# Historias y planificación

Desde Proyectos, la opción Historias permite consultar el Product Backlog.

El Product Owner del proyecto puede crear historias con título, Como, Quiero, Para y criterios de aceptación. Cada criterio se captura en una línea. Las historias nuevas se colocan al final. El orden puede cambiarse por arrastre o con las flechas; la prioridad se elige con MoSCoW.

El Developer asigna puntos con la escala 1, 2, 3, 5, 8, 13 y 21. Las historias deben tener una estimación de hasta 13 puntos para seleccionarse en un sprint.

Desde Sprints, el Scrum Master registra nombre, fechas y meta. La fecha final debe ser posterior a la inicial. El sprint se crea en planificación.

El Developer abre Planificar para agregar o retirar historias. Cada cambio se guarda y actualiza los puntos comprometidos. Una historia no puede pertenecer a dos sprints a la vez.

Los proyectos archivados conservan la consulta de sus historias y sprints. Sus datos no se pueden modificar desde estas pantallas.
